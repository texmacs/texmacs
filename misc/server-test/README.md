# Server E2E and load testing

End-to-end and load tests for the TeXmacs client-server communications
Each test launches a real TeXmacs client process that connects over TLS to a
live server, executes Scheme scenario scripts, and checks the outcome.

If you encounter any issue in the following instructions, please look at the Troubleshooting section at the end.

## Directory layout

```
misc/server-test/
  main_test.go                  Go test runner (TestLoad, TestScenarios)
  go.mod / go.sum               Go module (only testify as dependency)
  compose.yaml                  Docker Compose: texmacs-server + mailpit
  mail.rc                       Mail config mounted into container
  my-init-texmacs.scm           Generated by 'make my-init-texmacs.scm',
                                includes fixtures below

  fixture/helpers/
    helpers.scm                 Server-side fixture API (fixture-create-account,
                                fixture-create-file, fixture-create-chat,
                                fixture-share, etc.)
    generate-cert.scm           Self-signed TLS certificate generation
    admin.scm                   Admin account creation
    client-helpers.scm          Client-side test helpers (fail!, check!,
                                setup-test, with-server-eval)

  scenarios/
    config.tmpl.scm             go templated configuration for tests
    config-instances.tmpl.scm
    load/                       Stress scenarios — fire RPCs, no assertions, can loop forever
    services/                   Services scenarios — assert correct behaviour, ends
      scenario-delete-account.tmpl.scm

  debug/                        Contains generated test scripts that can be run manually
                                if needed
```


## Requirements

- exported `TEXMACS_PATH` environment variable
- exported `ADMIN_PASSWORD` environment variable
- Running texmacs server instance, preferably using docker compose.yaml present here, but
  you can run your own manually.
- `docker` installed if going that route.
- have a guile-texmacs folder in the same location as TeXmacs sources if you use docker compose to build the docker image

## How it works

`make` or `make check` will run the go tests.
The test configuration will be rendered along with the current test scenario script inside the `debug` folder once per client
(controlled with `-nclients 3` or `TEXMACS_NCLIENTS` variable) and per server instance
(`-instances "localhost:6561,localhost:6562"` or `TEXMACS_INSTANCES` variable).
The output of the scenario (TeXmacs stdout and stderr) will be in a file next to the generated script in `debug` folder
Each client will have their randomly generated TEXMACS_HOME_PATH

Tests are run in parallel (use of `t.Parallel()`).

## Running

In order to setup a server instance with docker, you can do the following from *inside* the directory that contains compose.yaml (misc/server-test):

```bash
# Start the server
docker compose up -d

make check

# Run only load tests
make check TESTS=TestLoad

# Reproduce a specific run
make check TEST_SEED=8429371650123

# use multiple clients
make check TEXMACS_NCLIENTS=3

# use multiple instances
make check TEXMACS_INSTANCES="localhost:6561,localhost:6562"
```

Running individual test can be done with the `TESTS` makefile variable (passed to `go test -run`) which is a very convenient regex, separated by '/'.
There are 2 main tests (TestServices and TestLoad) and both of them have subtests which are the scenario .scm files.
If you want to filter only the scenario-print-public-preferences.scm test you can do either of these:

```bash
make TESTS=TestLoad/scenario-print-public-preferences
make TESTS=/scenario-print-public-preferences
make TESTS=/print
```

### Scaling
Tests can be run on multiple texmacs server instances, you can spawn multiple servers using docker compose this way:

```bash
# launch 3 texmacs server
docker compose up --scale texmacs-server=3 -d
```

Ports exposed externally (on the host) will be in the range specified in `ports` section in compose.yaml. The port selected will loop through the range so you won't always get the port you want. The best way to always have the same instances on the same port is to restrict the port range to the number of instances. By default, compose.yaml has a 3 port range, so scaling up to 3 texmacs server instances will always get the same ports. Feel free to change it on your local testing. This is annoying but is the easiest solution for now

### HTML test results

You can visualise test results in your browser with

```bash
make -i serve-tests
```

`-i` is used to ignore test results errors, otherwise make will stop if any test fails
otherwise you can do `make json-tests TESTS=/print; make serve-tests`

# Troubleshooting

## Connection
Make sure the tests are run on the correct `host:port` combination otherwise you will get:

```
TeXmacs] debug-io, client started, its status is now 'cannot connect to hostname 'localhost' at port 6561'
```

When using docker compose to start a server, you might not always get the port you want because of the port range in place in compose.yaml. As written above, please restrict the port range to the number of instances of texmacs server you want.

For one instance:
```
services:
  ...
  texmacs-server:
    ...
    ports:
      6561:6561
```

## Certificates
Don't be bothered by the x509 certificate/key errors in the TeXmacs *CLIENT* output, it does not need them to connect to the server. The server process should however find its certificate files
